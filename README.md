# Semantic Router

An experiment that routes each question to one of **9 models** (OpenAI / Google / Anthropic × small / medium / large) based on **category** and **complexity**.

In the `feat: add phase-1 chat demo with model auto-routing` stage, classification and routing used [vLLM Semantic Router](https://github.com/vllm-project/semantic-router) + Envoy — picking one of three models from a single domain label. We now need a **complexity score** as well (company × size = 9 models). Semantic Router is built for single-category routing, so that second axis did not fit cleanly. We dropped the Envoy path and select the model inside FastAPI with mmBERT (category) + E5 embeddings (complexity), then call each provider API directly.

```
browser(:3000)  →  frontend (Next.js)
                      ↓
                 backend (FastAPI, :8000)  ←→  postgres (:5432)
                      ↓
         auto: category → company, complexity → size
         manual: pick company & size
                      ↓
              OpenAI / Google / Anthropic
```

| Company | Small | Medium | Large |
| --- | --- | --- | --- |
| OpenAI | gpt-6-luna | gpt-6.1-sol | gpt-6-astra |
| Google | gemini-3.5-flash-lite | gemini-3.8-flash | gemini-3.1-pro-preview |
| Anthropic | claude-sonnet-5-5 | claude-opus-5-5 | claude-fable-5-1 |

Model IDs and routing maps live in [backend/app/routing/models.json](backend/app/routing/models.json).

## Features

- **Category classification** — mmBERT classifies each question into one of 14 MMLU-Pro categories, which maps to a company (OpenAI / Google / Anthropic).
- **Complexity scoring** — a kNN vote over E5 embeddings of labeled reference questions picks a size (small / medium / large) within that company. Evaluated on a 100-question rubric-labeled set with 5-fold cross-validation (3-tier agreement 71% → 80.8%, large recall 17% → 79% versus the previous similarity-score method) and on a held-out set of realistic work requests that exposed and fixed a length bias (long easy requests routed small 17% → 83%). See [notebooks/eval](notebooks/eval/README.md).
- **Streaming responses** — replies stream token-by-token over SSE instead of waiting for the full response.
- **Persistent conversations** — chat rooms and messages are stored in Postgres, with auto-generated chat titles.
- **Context retention** — each reply is generated with a token-budgeted sliding window of prior turns, not just the latest message.
- **Auto memory extraction** — summarizes facts from past conversations into a running memory reused in future replies. Real services like Claude run this on a ~24h cycle; wired to a manual button here for demo/testing.
- **Personal instructions** — users can set a personal instruction from the sidebar that shapes how replies are written.
- **Import from other AI** — paste a summary generated by another AI assistant to carry that context into replies here.
- **Token usage tracking** — a sidebar ring shows the current billing cycle's remaining tokens; a dedicated view breaks usage down by today/week/month/year and by model.
- **Conversation search** — partial-match search across chat titles and message content (Postgres `pg_trgm`), grouped one result per chat room.
- **Web search tool use** — the routed model itself decides whether a question needs a web search (same pattern as ChatGPT/Claude), then answers with cited sources. Search runs on Tavily and automatically falls back to Perplexity, then Brave, if a provider errors or times out (providers without an API key are skipped).
- **File attachments** — drag-and-drop or attach files into a chat (txt, md, csv, xlsx, docx, pptx, hwp/hwpx, pdf, images). Text and embedded images are extracted per format and sent to the model alongside your message; extraction runs in the background so sending isn't blocked on slow conversions.
- **Attachment preview** — click an attached file's chip (before or after sending) to open it in a modal viewer: text/markdown inline, CSV/XLSX as a table, images and PDFs rendered directly, and DOCX/PPTX converted to PDF on first view.
- **Project folders** — group related chat rooms under a project that has its own instruction, reference files, and memory, scoped only to that project's chats. Each project gets its own page (`/projects/{id}`); chats can be dragged in and out of a project, and folders can be pinned, color-coded, and renamed from the sidebar.
- **Memory settings** — a dedicated view lists every auto-extracted memory fact, both global and per-project, with a delete button on each so you can correct or remove anything the model shouldn't keep remembering.
- **Document generation** — ask for a file ("make this a Word file", "put it in Excel", "build a 5-slide deck") and the model creates DOCX, PDF, Markdown, TXT, XLSX, CSV, PPTX, or HWPX (한글). The file appears as a download card in the chat and stays there after a refresh.
- **File conversion** — attach a file and ask for another format (e.g. Excel → Word report, PDF table → Excel, Word → slides, HWPX → DOCX); the attachment's extracted content becomes the new file.
- **In-place file editing** — attach an XLSX, DOCX, PPTX, or HWPX and ask for a change ("change Q3 revenue to 1,200", "rename the title"). The model inspects the file, edits only the targeted cells or text, and saves a new `원본_수정` copy, leaving the original untouched and keeping charts, images, and formatting. You can keep editing the new copy in follow-up turns.
- **Image generation** — ask for an image, illustration, banner, or background, and it is generated with OpenAI's image model and shown as a card with an inline preview and a download button.

More features are planned (rate limiting, etc.) — this list will grow with a short bullet per feature as they land.

## Memory

Six mechanisms decide what the model "remembers" and where that carries over to:

| Feature | Scope | Trigger | Description | Core mechanism |
| --- | --- | --- | --- | --- |
| Context retention | Within a chat room | Automatic | Keeps referring back to prior questions/answers within the same chat room | Sliding window |
| Auto memory extraction | Across chat rooms | Automatic | Remembers key facts (preferences, job, etc.) even when you switch or open a new chat room | Memory formation |
| Personal instructions | Across chat rooms | Manual | Write a self-intro and preferred reply style once; applied to every chat room | System prompt injection |
| Import from other AI | Across chat rooms | Manual | Extracts context from another AI platform via a dedicated prompt and carries it into replies here | Memory import |
| Project memory | Chats inside one project | Automatic | Same auto-extraction as above, but scoped to that project's chats only and kept separate from global memory | Memory formation |
| Project instructions | Chats inside one project | Manual | Set an instruction on a project folder; applied only to chat rooms assigned to that project, on top of the global instruction | System prompt injection |

When two or more of these disagree on the same fact, they're applied in order: personal instructions → imported memory → auto-extracted (global) memory → project instructions → project memory (see [chat/router.py](backend/app/chat/router.py)). Both the global memory and every project's memory can be reviewed and individual facts deleted from the memory settings view.

## Attachments

Each of the 9 supported formats is handled differently depending on how well the model can consume it directly:

| Type | Format | Handling |
| --- | --- | --- |
| Inserted as-is | TXT | Read file as-is |
| Inserted as-is | MD | Read file as-is |
| Text + structured (row-limited) | CSV | Read as text + encoding fallback (UTF-8 → CP949) + capped at 1,000 rows |
| Text + structured (row-limited) | XLSX | openpyxl, per sheet + capped at 1,000 rows + converted to a markdown table |
| Hybrid (text extracted, images passed separately) | DOCX | Paragraphs and tables extracted via python-docx; images inside the document are extracted individually and interleaved with the text in original order |
| Hybrid (text extracted, images passed separately) | PPTX | Per-slide text extracted via python-pptx; images inside slides are extracted individually and interleaved with the text in original order |
| Hybrid (text extracted, images passed separately) | HWP/HWPX | Body text and tables extracted via hwp-hwpx-parser; images inside the document are extracted individually and interleaved with the text in original order |
| Passed directly to the vision model | PDF | No extraction - the original file is passed directly to the vision model |
| Passed directly to the vision model | IMG (jpg/png, etc.) | Converted to PNG and resized (max 1568px) via Pillow, then passed directly to the vision model |

If a hybrid format (DOCX/PPTX/HWP) has no extractable text at all (e.g. a scanned document), it's converted to PDF with LibreOffice and treated like a native PDF attachment instead (see [extraction.py](backend/app/extraction.py)).

## File generation & editing

The routed model calls these as tools. Each tool is only offered when the message looks like a file, image, or edit request, so ordinary questions are unaffected. Every result is saved as a new file in the chat and shown as a download card. Clicking the card opens the same preview viewer as attachments.

| What you ask for | Formats | How it works |
| --- | --- | --- |
| Create a document | DOCX, PDF, MD, TXT, HWPX | The model sends structured content (headings, paragraphs, lists, tables). The server renders it. Office files use 맑은 고딕. PDF is a DOCX converted with LibreOffice using a Korean font. |
| Create a spreadsheet | XLSX, CSV | Values are typed per column (number, currency, percent, date) and formatted by the server. Totals are real `SUM` formulas. Text cells can never become formulas. |
| Create a presentation | PPTX (16:9) | Title, section, bullets, two-column, and table layouts, with speaker notes. |
| Convert an attachment | Any of the above | Same tools, using the attachment's extracted content. |
| Edit an existing file | XLSX, DOCX, PPTX, HWPX | The model first inspects the file (cells, paragraphs, slides, table cells, notes), then submits edits, which are rejected unless the current value matches what it saw. Only the edited XML parts are rewritten, so charts, images, and styles stay byte-for-byte intact. The original is never modified; the result is `원본_수정.ext`. Formula cells, hyperlinks, and text boxes are read-only, and adding or deleting rows or slides isn't supported. |
| Generate an image | PNG, JPG | Square, landscape, or portrait image via OpenAI's Images API. Up to 2 images per reply. |

Limits:
- 25MB per generated file.
- 5 generated files per reply.
- Generated files are deleted with their chat.

## Run

There are two compose files — pick the one matching where you're running this:

- **`docker-compose.dev.yml`** — local development. CORS/API URL are hardcoded to `localhost`.
- **`docker-compose.yml`** — on-premise/server deploy. Uses `SERVER_IP` from `.env` for CORS/API URL; without it, requests silently fail with a CORS error.

### Local development

```bash
cp .env.example .env

docker compose -f docker-compose.dev.yml up -d --build
```

### On-premise / server deploy

```bash
cp .env.example .env

docker compose up -d --build   # uses docker-compose.yml
```

- Frontend: http://localhost:3000 (or `http://$SERVER_IP:3000` on a server)
- Backend: http://localhost:8000/health (or `http://$SERVER_IP:8000/health`)

On first start, classifier models are downloaded from Hugging Face and cached in the `backend_hf_cache` volume. Manual model selection works before the classifiers finish loading.

The commands below all default to `docker-compose.yml` — for local dev, add `-f docker-compose.dev.yml` to each:

```bash
# Status / logs
docker compose ps
docker compose logs -f backend

# Health check (pretty-printed)
curl -s http://localhost:8000/health | python3 -m json.tool

# Rebuild after code changes
docker compose up -d --build
docker compose up -d --build backend   # backend only

# Stop
docker compose stop          # stop containers (volumes kept)
docker compose down          # remove containers (model cache kept)
docker compose down -v      # also delete volumes (models re-download, DB data wiped)

# memory test
docker compose down
docker volume rm semantic-router_postgres_data
docker compose up -d
```
